# Дашборд портфельных операций ОСИП — обзор функциональности

Описание того, что приложение умеет сегодня, языком, понятным портфельному
управляющему, а не техническим переводом. Основано на реальных страницах
и API, а не на планах. Статус поставки и доказательства приёмки — в
[implementation-plan.md](implementation-plan.md) и
[requirements-traceability.md](requirements-traceability.md).

**Текущая модель работы:** приложение обычно запускается локально владельцем
одной области, который работает со своими рабочими книгами. См.
[local-domain-operating-model.md](local-domain-operating-model.md). Строгие роли
проверяющего/публикатора и OIDC остаются возможностью для ОСИП или будущего
общего контура; для локальных доменных представлений подтверждение каждого
клиента не требуется.

## Что это за приложение

Приложение превращает файлы ОСИП и доменные рабочие книги в проверяемый
дашборд с историей версий. Для локальных доменных источников путь проще:
загрузка → разбор → просмотр исходных данных. Для ОСИП сохраняется явное
назначение портфеля. Любой показатель можно проследить до конкретной строки
исходного файла.

Приложение **не** считает официальную СЧА (NAV) и доходность, не читает и
не пишет данные в «порт-акк» (port-acc). Каждый показатель явно помечен —
из файла, расчётный или недоступен. Если формула в файле сломана, дашборд
честно покажет «недоступно», а не подставит ноль.

## Роли и доступ

| Роль | Что может делать |
|---|---|
| `uploader` | Загружать файл ОСИП |
| `reviewer` | Утверждать или отклонять проверенную загрузку (двойной контроль: нельзя утвердить собственную загрузку) |
| `publisher` | Публиковать уже утверждённую загрузку |
| `reader` | Смотреть загрузки, скачивать исходные файлы, работать с опубликованными версиями портфеля и отчётами |

Локально роль сотрудника передаётся заголовками `X-Actor-Id` /
`X-Actor-Roles`, при необходимости с ограничением по конкретным портфелям
через `X-Actor-Portfolios`. В боевом контуре те же роли и доступ по
портфелям берутся из подписанного OIDC-токена — вход через локальные
заголовки в продакшене полностью заблокирован.

## Загрузка и публикация файлов (страница «Загрузки источников»)

- **Загрузка** файла `.xls`. Файл получает уникальный отпечаток (хеш) и
  хранится в неизменном виде; имя файла остаётся как доказательство, но
  портфель и отчётную дату дашборд не берёт из имени — они считываются из
  содержимого файла, а какому портфелю принадлежит загрузка, указывает сам
  сотрудник.
- **Повторная загрузка того же файла** не создаёт дубликат — система узнаёт
  уже загруженный файл и возвращает существующую запись. Если файл
  исправили, повторная загрузка станет новой версией того же портфеля и той
  же отчётной даты.
- **Статусы загрузки**: черновик → проверка → проверено → утверждено →
  опубликовано, а также «отклонено» и «ошибка» как конечные статусы.
  Отклонённые и ошибочные загрузки не удаляются — они остаются в реестре как
  доказательство.
- **Сравнение** новой загрузки с предыдущей утверждённой версией до принятия
  решения.
- **Утверждение / отклонение**: утвердить загрузку должен другой сотрудник,
  а не тот, кто её загрузил (двойной контроль), и обязательно с
  обоснованием. Любое блокирующее или высокое по серьёзности замечание по
  качеству данных нужно явно подтвердить до утверждения.
- **Публикация** — отдельный шаг после утверждения, доступный только роли
  `publisher`. СОБСТВ и TABYS публикуются независимо друг от друга, и
  список портфелей сразу покажет, если их отчётные даты разошлись.
- **Скачать исходный файл**, который лежит в основе любой загрузки, можно в
  любой момент — для проверки или аудита.

## Каталог портфелей

- Список портфелей с датой последней публикации и явным предупреждением,
  если СОБСТВ и TABYS опубликованы на разные даты.
- Список показателей, которые дашборд умеет считать, и на какой основе —
  из файла или расчётный — чтобы не показывать то, что нечем подтвердить.
- История версий портфеля — все публикации за прошедшее время.

## Обзор портфеля (главная страница)

- Итоговые показатели портфеля с указанием основы расчёта (из файла /
  расчётный / недоступен), отчётной датой и версией.
- Структура портфеля с переключением между «суммой покупки» и «расчётной
  балансовой стоимостью», агрегированная по инструментам, но с сохранением
  связи с отдельными лотами.
- Панель со статусом публикации и состоянием проверки качества данных.
- Краткая справка на странице — как читать цифры.

## Позиции

- Позиции, сгруппированные по инструментам.
- По клику — раскрывающаяся панель с отдельными **лотами**, из которых
  сложилась позиция, каждый со ссылкой на исходную строку файла.

## Деньги и календарь

- Остатки денежных средств по кастодиану, в валюте счёта и в
  тенге-эквиваленте, с возможностью показать нулевые строки-шаблоны из
  файла.
- Сводка по валютам (отмечена как несверенная банковская позиция — это не
  замена банковской выписке).
- Календарь событий по лотам — погашения, купоны, даты РЕПО — из файла.
  Раздел «предстоящие расчёты по сделкам» из ОСИП в этот календарь
  намеренно не входит и обрабатывается отдельно.

## Качество данных

- Каждое замечание привязано к правилу, уровню серьёзности, затронутым
  полям, месту в исходном файле и статусу подтверждения — с поиском и
  фильтром по серьёзности.
- Список показателей, которые дашборд показывает только тогда, когда для
  них есть и данные, и подтверждённая методика расчёта.

## Отчётность

- Показывает, готова ли опубликованная версия портфеля к выгрузке, и что
  именно мешает, если нет.
- Формирует управляемый отчётный пакет: неизменяемый, версионированный,
  включает исходный файл, канонические данные, замечания по качеству
  данных и данные об утверждении. Это утверждённый пакет, а не
  произвольная выгрузка — какие виды отчётов доступны, определяет
  политика.
- В каждом сформированном пакете сохраняется, кто утвердил и опубликовал
  версию, из которой он собран.

## API чтения версии портфеля, на которых держатся страницы

Всё только для чтения и привязано к конкретной опубликованной версии
портфеля (или, для служебной проверки, неопубликованной — только для роли
`reader`): итоги, позиции, структура, деньги, расчёты по сделкам,
замечания по качеству данных, календарь, готовность к отчёту.

## Обработка расчётов по сделкам

Исходные строки расчётов из файла схлопываются в дедуплицированные записи
без потери ни одной исходной строки — например, 10 строк расчётов СОБСТВ
из файла становятся 5 записями, но обе исходные строки остаются доступны
по ссылке.

## Что намеренно не входит в текущий объём

- Официальный расчёт СЧА (NAV) и доходности.
- Любой обмен данными с «порт-акк» (port-acc).
- Ручной ввод или редактирование данных — дашборд только читает и
  контролирует загрузки файлов, но не позволяет их редактировать.
